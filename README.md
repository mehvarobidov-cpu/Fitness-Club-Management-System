# Разработка веб-приложения для управления фитнес-клубом

Веб-приложение для автоматизации деятельности фитнес-клуба: управления клиентами, тренерами, абонементами, услугами, расписанием тренировок и посещаемостью.

---

## О проекте

**«Разработка веб-приложения для управления фитнес-клубом»** — учебный проект, предназначенный для создания единой информационной системы, которая упрощает работу администрации фитнес-клуба, тренеров и клиентов.

Система позволит централизованно хранить информацию о клиентах, контролировать абонементы, планировать тренировки, вести запись на занятия и учитывать посещаемость. Администратор сможет управлять основными данными клуба, тренеры — просматривать расписание и списки участников, а клиенты — знакомиться с услугами и записываться на доступные занятия.

Проект будет разрабатываться поэтапно. Результаты анализа, проектирования, разработки и тестирования будут размещаться в соответствующих каталогах репозитория GitHub.

## Цель и задачи проекта

### Цель проекта

Разработать веб-приложение для централизованного управления основными процессами фитнес-клуба, обеспечивающее удобную работу администрации, тренеров и клиентов.

### Задачи проекта

1. Изучить предметную область и определить основные процессы работы фитнес-клуба.
2. Проанализировать существующие программные решения для управления фитнес-клубами.
3. Сформировать функциональные и нефункциональные требования.
4. Определить роли пользователей и права доступа.
5. Спроектировать архитектуру веб-приложения.
6. Разработать модель базы данных MySQL.
7. Реализовать регистрацию, авторизацию и управление учетными записями.
8. Разработать модуль управления клиентами и тренерами.
9. Реализовать учет услуг и абонементов.
10. Разработать модуль расписания групповых и персональных тренировок.
11. Реализовать запись клиентов на занятия и учет посещаемости.
12. Разработать административную панель и основные отчеты.
13. Провести тестирование и подготовить документацию.

## Участники системы (User Roles)

В системе предусмотрены следующие основные роли:

| Роль | Описание и возможности |
|---|---|
| **Администратор (Administrator)** | Полный доступ к системе. Управление пользователями, клиентами, тренерами, услугами, абонементами, расписанием, записями и отчетами. |
| **Менеджер (Manager)** | Работа с клиентами, оформление и продление абонементов, регистрация оплат и учет посещений в пределах предоставленных прав. |
| **Тренер (Trainer)** | Просмотр личного расписания, информации о тренировках и списков записанных клиентов; отметка посещаемости. |
| **Клиент (Customer)** | Просмотр услуг и расписания, просмотр собственного абонемента, запись и отмена записи на доступные тренировки, просмотр истории посещений. |

## Функциональные возможности

### 1. Управление пользователями
- Регистрация и авторизация пользователей.
- Выход из учетной записи.
- Разграничение доступа по ролям.
- Просмотр и редактирование профиля.

### 2. Управление клиентами
- Добавление, просмотр, редактирование и удаление данных клиентов.
- Поиск клиентов по имени, номеру телефона или электронной почте.
- Просмотр абонементов и истории посещений клиента.

### 3. Управление тренерами
- Создание и редактирование профилей тренеров.
- Хранение контактных данных и специализации.
- Назначение тренеров на тренировки.
- Просмотр расписания тренера.

### 4. Управление услугами и абонементами
- Создание видов абонементов.
- Указание стоимости и срока действия.
- Определение количества доступных посещений и включенных услуг.
- Оформление и продление абонементов.
- Контроль активных и истекших абонементов.

### 5. Управление расписанием
- Создание групповых и персональных тренировок.
- Назначение тренера.
- Указание даты, времени и продолжительности занятия.
- Установка максимального количества участников.
- Изменение и отмена тренировок.

### 6. Запись на тренировки
- Просмотр доступных занятий.
- Запись клиента на тренировку.
- Проверка свободных мест.
- Отмена записи.
- Просмотр списка участников занятия.

### 7. Учет посещаемости
- Отметка посещения или отсутствия клиента.
- Просмотр истории посещений.
- Учет использованных занятий по абонементу.

### 8. Оплата и отчетность
- Регистрация сведений об оплате.
- Просмотр истории платежей.
- Отображение количества активных клиентов и абонементов.
- Формирование сводной информации о тренировках и посещаемости.

## Принцип работы системы

Работа веб-приложения строится вокруг взаимодействия администрации, тренеров и клиентов.

1. **Регистрация и вход.** Пользователь создает учетную запись или входит в систему. Приложение определяет его роль и предоставляет соответствующие возможности.
2. **Управление клиентами.** Администратор или менеджер добавляет данные клиентов и поддерживает информацию в актуальном состоянии.
3. **Оформление абонемента.** Для клиента выбирается тип абонемента, фиксируются стоимость, срок действия и доступное количество посещений.
4. **Планирование занятий.** Администратор создает тренировку, назначает тренера, дату, время и количество мест.
5. **Запись на тренировку.** Клиент просматривает расписание и записывается на подходящее занятие. Система проверяет доступность мест.
6. **Проведение тренировки.** Тренер просматривает список участников и отмечает фактическое посещение.
7. **Контроль абонементов.** Система позволяет проверять срок действия абонемента и остаток посещений.
8. **Отчетность.** Администрация получает сводные сведения о клиентах, абонементах, платежах, тренировках и посещаемости.

## Запуск проекта

На начальном этапе репозиторий содержит проектную документацию и структуру будущего приложения. Инструкция станет полностью применимой после реализации исходного кода.

### 1. Требования

Перед запуском необходимо установить:

- Go;
- Git;
- Visual Studio Code;
- XAMPP с MySQL;
- Postman (для тестирования API).

### 2. Клонирование репозитория

```bash
git clone https://github.com/USERNAME/fitness-club-management.git
cd fitness-club-management
```

Вместо `USERNAME` необходимо указать имя GitHub-аккаунта, а URL — заменить адресом созданного репозитория.

### 3. Создание базы данных

1. Запустить MySQL в XAMPP.
2. Открыть phpMyAdmin.
3. Создать базу данных с названием `fitness_club`.
4. После подготовки SQL-файлов выполнить `database/schema.sql`.
5. При необходимости загрузить демонстрационные данные из `database/seeds.sql`.

### 4. Настройка окружения

Создать файл `.env` на основе `.env.example` и указать параметры подключения:

```env
HTTP_ADDR=:8080
DATABASE_URL=user:password@tcp(127.0.0.1:3306)/fitness_club?parseTime=true
```

Указать собственные имя пользователя и пароль MySQL. Файл `.env` не следует загружать в публичный репозиторий.

### 5. Установка зависимостей

```bash
go mod tidy
```

### 6. Запуск приложения

После реализации серверной части:

```bash
go run ./cmd/server
```

При успешном запуске приложение будет доступно по адресу:

```text
http://localhost:8080
```
